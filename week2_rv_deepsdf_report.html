What was fixed

The earlier pilots were rejected because their command-line dispatcher silently forced data_load_rv.json, the old coordinate corpus, although RV specs named the corrected corpus. The model was trained on one map and evaluated on another.

The standalone trainer now follows each surface's DataSource and logs the chosen manifest. The final run logged Using training manifest: ...data_load_rv_production_lps_v2.json.

The corrected corpus preserves original NIfTI bytes, uses SimpleITK LPS geometry and the production get_T transform, and searches the RV field in [-2.25, 2.25]. This bound is based on all 1,716 eligible labels: maximum absolute canonical coordinate 2.0426, plus margin.

How it works, simply

Start with the RV label

Each segmentation becomes a closed triangle skin, like a balloon made from tiny triangles.

Put every balloon on the same map

The existing production get_T transform moves every RV into one common coordinate space, so the model learns anatomy rather than scanner position.

Teach inside and outside

Points receive a signed distance: negative inside, positive outside, and zero on the wall. DeepSDF learns that numeric field instead of directly memorising triangles.

Draw the wall again

Marching cubes finds the predicted zero boundary and turns it into a 3D RV mesh. A mesh is accepted only if it is non-empty and watertight.

Why it will fit later

Same coordinate convention

The final corpus uses original NIfTI geometry, SimpleITK LPS, and read-only production get_T. That removes hidden coordinate drift.

Same decoder interface

The checkpoint has the same parameter layout as the application decoder and passed strict loading. No partial or loose weight load is used.

RV has its own grid setting

The RV model records ReconstructionGridBound = 2.25, so it is not cropped by the legacy [-1,1] reconstruction box.

No false motion claim

This is shape-only at t=0. It does not claim patient-specific RV motion across phases.

One small future system change

When the team integrates this approved checkpoint, pass the RV grid bound from model specs into the existing mesh helper: volume_size = 4.5 for RV instead of its current default 2.0. This changes the search box from [-1,1] to [-2.25,2.25].

This is intentionally deferred. Application code remains untouched today, and the value is already stored with the model for a small reviewable future change.

What to validate next

  1. Scale the completed patient-level pilot split into a full train, validation, and test split. ED and ES from one patient must stay together.
  2. Train with all 1,716 eligible shapes, retaining manifest, sign, coordinate round-trip, and mesh gates.
  3. Measure a sufficiently sized held-out set: Chamfer RMS, HD95, volume error, and visual checks for small and large RVs.
  4. Review the 31 exclusions separately: 5 non-manifold meshes and 26 NIfTI direction-cosine failures.
  5. Only after held-out validation, stage the one grid-bound change behind a configuration flag and run non-training end-to-end tests.

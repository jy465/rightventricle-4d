How an RV mask becomes DeepSDF training data

This page is based on the builder currently preparing the full RV corpus. It explains what the input is, how the surface is made, where the dots come from, and why the model needs them.

Direct answer: is the RV surface based on the mask?

Yes. The RV surface comes from the boundary of the RV part of the mask.

The label image is a 3D grid of tiny cubes, called voxels. The builder selects only cubes with value 1, meaning RV cavity. It wraps a triangle skin around the outside of those RV cubes.

So it uses the RV mask surface.

No. It does not combine RV, LV cavity, and LV myocardium into one surface.

Labels 2 and 3 are not included in the RV mesh. The production coordinate function get_T can look at them only to orient the heart consistently.

The final shape is an RV cavity surface, not a whole-heart mesh.

Step 1: mask to RV surface

1

Read one labelled 3D segmentation

It can contain background (0), RV (1), LV myocardium (2), and LV cavity (3). It is an expert segmentation mask, not the original MRI scan.

2

Select RV only

The real code uses labels == RV_LABEL and sets RV_LABEL = 1. This makes a binary RV-only mask.

3

Clean small mask artefacts

The builder keeps meaningful connected RV parts, closes tiny voxel gaps once, and rejects a result with fewer than 32 RV voxels.

4

Create the triangle boundary

marching_cubes(..., level=0.5) puts triangles between RV voxels and non-RV voxels. One light smoothing pass is applied.

Actual mesh-selection logic, shortened only for visual layout
RV_LABEL = 1
binary = binary_closing(keep_main_component(labels == RV_LABEL), iterations=1)
vertices, faces = marching_cubes(pad(binary), level=0.5)
mesh = Trimesh(vertices=world_coordinates, faces=faces)

Step 2: put every RV on one shared map

Scans can be rotated, shifted, or have different physical spacing. The builder calls the existing production get_T function read-only to put every RV mesh into a shared canonical coordinate space.

Important separation: get_T may inspect LV myocardium and LV cavity to decide heart orientation. It does not add them to the RV surface. It only tells the RV surface where the shared up, side, and centre are.

The builder rejects a case if moving it to canonical space and back changes it by more than 1e-5 mm, or if it lies outside the RV grid bound of 2.25.

Step 3: how the 50,000 dots are actually placed

The dots are random, but deliberate and repeatable. A stable seed based on dataset and shape ID lets the same case be rebuilt with the same dot distribution.

47,000 dots near the RV surface

94%

The code samples 10,000,000 candidate locations on the RV mesh triangles. It chooses surface locations and nudges them by small random offsets at two close distances from the wall.

Why: the RV boundary is the shape the model must learn, so most examples need to be near that boundary.

3,000 dots in the wider unit sphere

6%

These dots are spread through wider 3D space around the RV, not concentrated only near the wall.

Why: they teach the model what is clearly inside and clearly outside, rather than only a thin shell.

One dot is a question and answer: At this 3D coordinate, how far am I from the RV surface, and am I inside or outside? It is a newly generated training point, not simply an original mask voxel.

Step 4: give each dot its correct answer

Signed distance function (SDF)

Each dot gets a distance to the RV surface. The sign says which side: +0.20 is outside, -0.20 is inside, and 0 is exactly on the surface.

The sampler uses nearby mesh normals to assign the sign.

Independent safety check

The builder then independently asks the watertight mesh whether all 50,000 dots are inside or outside. More than 0.5% disagreement warns; more than 5% rejects the archive.

The check is batched only to avoid memory errors. It still checks all 50,000 points.

Step 5: save one valid training archive

One RV archive contains

  • pos: outside dots as [x, y, z, positive_distance]
  • neg: inside dots as [x, y, z, negative_distance]
  • t = 0.0: independent shape, not motion data
  • P, Pi, offset, scale: coordinate metadata

What happens later during actual DeepSDF training

A

Choose an archive from the training split

Only the 1,201 training shapes will adjust the model. Validation (257 shapes) and test (258 shapes) patients stay separate.

B

Ask the neural network about a dot

DeepSDF receives the dot location x, y, z and a learned code representing that RV shape. It predicts one signed distance.

C

Compare prediction with the stored correct answer

If the archive says -0.20 but the network predicts +0.10, it is wrong. Optimisation changes the weights and shape code to reduce that error.

D

Repeat across many RV shapes

The model learns shared RV shape rules. Later, a zero-distance boundary across a 3D grid becomes a reconstructed RV mesh.

Honest limitation: this learns a shape representation from expert segmentation masks. It does not currently train an MRI image directly into an RV mesh, and every archive uses t = 0.0, so it is not learning ED-to-ES motion.

Why this preparation must finish first

DeepSDF should not learn from empty RVs, surfaces with holes, wrong inside/outside answers, or hearts in inconsistent directions. Otherwise it could learn data mistakes instead of real RV anatomy.

This is why the full model has not started training yet. First, all 1,716 eligible archives need to pass. The builder then writes separate train, validation, and test manifests. Only then can full DeepSDF training start fairly.
